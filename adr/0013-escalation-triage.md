# ADR-0013: escalation の分流 — 正本テスト

- Status: accepted
- Date: 2026-07-02

## Context

実装パイプラインのレビューが escalation（人の判断待ち）を返したとき、findings には二種類が混在する:

1. change folder（設計成果物・タスク定義）の中で閉じる実装可能性ギャップ — その場の判断で裁ける
2. 解決の実体が上流の正本（形式仕様・design/・ADR）の未定義・曖昧さであるもの — change 内の裁定は暫定にすぎず、正本が追いつかなければ「仕様に書いていない意味論で実装が動く」乖離が生まれる

この二種を区別せずすべてその場で裁くと、正本の債務が change folder に埋没する。逆にすべて設計に返すとパイプラインが止まりすぎる。

## Decision

**正本テスト**で分流する: **finding の解決が change folder の外（spec / design / adr）への変更を要するなら「設計に返る」、中で閉じるなら「判断で済む」。**

このテストは機械的に判定できる（解決策が触るファイルの位置で決まる）。

設計に返る finding の扱い:

- **暫定裁定でパイプラインを進めてよい**。設計に返る = 停止ではない
- ただし**同じ内容の正本更新が merge までに着地すること**。design-not-later-than-merge（ADR-0007）の escalation への適用であり、正本と change の裁定が食い違ったまま merge しない
- 本ツールのループが適用される環境では、これはパイプライン起点 topic（ADR-0006）として機械排出される事象に相当する

## Consequences

- escalation 対応の手順が「分類 → 中で閉じるものは裁定 → 外に触るものは正本更新を併走 → resume」に定型化される
- 正本の債務が「merge 時に追記するつもり」という非公式な記憶ではなく、明示的な作業項目になる
- 分類自体の判断ミス（正本に触るのに中で裁く）は、出口ゲート（歯・`--verify`）が正本と実装の乖離として捕まえる範囲では回収される。文書の意味論の乖離は捕まえられないため、レビュー時の観点として残る
