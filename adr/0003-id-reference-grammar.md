# ADR-0003: ID・参照文法と strict Markdown プロファイル

- Status: accepted
- Date: 2026-07-02

## Context

本ツールの動詞（閉包検証・差分・トレース・導出・rules export）は、見かけは違ってもすべて**設計要素の参照グラフ上の操作**に還元される。したがってツールの成立を決めるのは、Markdown 上で要素の同一性と参照をどう表すかである。

また、汎用 Markdown パーサ（remark 系）への依存は依存極小方針に反し、Mermaid 全文法の解釈は行指向処理の範囲を超える。

## Decision

- 全設計要素に**型プレフィクス付きの安定 ID** を与える（例: `dom-order`, `mod-executor`, `seq-checkout`, `top-duplicate-slug`）。ID は見出しまたは frontmatter に置く
- 参照は **`[[id]]` の一文法のみ**。リンク義務の検証・差分・トレースはすべてこの文法に還元される
- **改名しても ID は不変**。これにより差分計算が「改名」と「削除 + 新規」を区別できる
- 文書は **strict プロファイル**（見出し構造・ID 位置・frontmatter スキーマ・参照文法）に従う。プロファイルは「行指向の貧弱なパーサで読める」ことを設計制約とする。フォーマットを機械可読に設計するのが先で、パーサを賢くするのは負け
- **図（Mermaid）は挿絵であり検証対象外**。機械が読む正本は構造化リスト（登場要素・依存の箇条書き）とする

## Consequences

- パーサが数百行で収まり、実行時依存ゼロを維持できる
- 図とリストの乖離は検出されない。実運用で痛みが確認されたら、Mermaid サブセット（sequenceDiagram の participant 行、classDiagram の関係行）の検証を追加する
- 書き手は strict プロファイルに従う必要がある。scaffold（テンプレート生成）と check（即時検証）で誘導する
