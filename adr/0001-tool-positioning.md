# ADR-0001: 位置づけと責務境界 — 設計の正本を守る決定的 CLI

- Status: accepted
- Date: 2026-07-02

## Context

AI エージェントによる実装パイプライン（精密な request を入力に、設計→実装→レビュー→PR を無人完走するツール。例: spec-runner）が確立すると、その上流の設計工程だけが形式を持たないまま残る。

実装パイプラインの各ステップが成立する条件は次の 3 つである:

1. 入力がファイルで完結する（人の頭の中の文脈が不要）
2. 出力に機械的な合否判定がある
3. 失敗しても人の介入なしにリトライできる

設計判断（境界・命名・トレードオフ・分岐の解決）は条件 2 を満たさない。合否 = 人の判断であり、これを無人パイプラインにすると、実装側で request の精密さが防いでいた迷走を上流で再生産する。

一方、設計作業の周辺には条件を満たす仕事が多くある: 決定の全層への整合反映（閉包検証が合否）、矛盾の指摘列挙（verdict は人）、設計差分からの request 起草（被覆検査が合否）。

また、エコシステムには agent 実行機構が既に複数存在する（実装パイプラインの step 実行、汎用 workflow ツール。例: takt）。設計ツールが三つ目の実行機構を持つのは再開発である。

## Decision

本ツールは**設計の正本（参照グラフと閉包）を守る決定的 CLI** とする。

- 責務: 形式仕様、参照グラフ構築、閉包検証、差分計算、導出支援、要素状態管理、文脈注入済みプロンプトの出力
- **agent 実行を内蔵しない**。AI 作業（伝播・レビュー・起草）は文脈注入済みの指示（instruction）を出力するまでを担う。指示は agent セッションが CLI を呼んで消費するのが主経路であり、skill / slash command としての同梱頒布を一級の配布形態とする。実行様式は利用者が選ぶ:
  - attended — 人と対話しながら agent が設計を書く（大きい判断向け）
  - semi-attended — workflow ツールの step でプロンプトを回し、人は checkpoint のみ
  - 無人ドラフト — 小さく閉じた topic を入力に agent が設計 delta の PR まで作り、人は PR レビューで verdict

ツール間の境界は機能ではなく**「どのツールが何の正本を守るか」**で引く:

| ツール | 正本 |
|---|---|
| 本ツール | 設計（参照グラフ・閉包・要素状態） |
| 実装パイプライン | request → merged PR の lifecycle 状態と成果物契約 |
| 汎用 workflow ツール | なし（プロセス機構の提供のみ） |

連携は**リポジトリ内ファイルと CLI 契約（exit code / stdout）のみ**。共有ライブラリを作らない。本ツールは他ツールを知らず、他ツールから本ツールはただの CLI に見える。

## Consequences

- ツールは完全に決定的になり、テストが素直に書け、CI にそのまま載る。provider 非依存が構造的に保証される
- 設計の品質そのものは保証しない。品質の verdict は常に人（設計 delta の PR merge が承認）
- パーサ等の小さなコード重複は、ツール独立性の対価として許容する。避けるのは agent 実行・review loop・worktree 管理といった重い機構の重複のみ
