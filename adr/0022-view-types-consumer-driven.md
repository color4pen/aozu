# ADR-0022: ビュー型の追補 — named consumer 駆動、prefix 列挙は名前空間の予約

- Status: accepted
- Date: 2026-07-06

## Context

ADR-0002 はコア 3 層以外を「ビュー」として manifest で有効化する成果物モデルを定め、spec/format.md §4 は 9 種のビュー型 prefix（`uc` / `scr` / `api` / `dat` / `flow` / `evt` / `ext` / `perm` / `dpl`）を列挙している。一方でビュー型のスキーマは未定義であり、C6 は fail-closed（enabled に入れると error）である。この非対称が「列挙された型はいずれサポートされる」という約束と誤読されうる。ADR-0002 だけを読むと screen 対応は既定路線に見える。

追補を需要駆動とする方針自体は docs/open-questions.md（旧・論点 2）で運用されてきたが、未確定の論点の棚に置かれたままで、決定記録に存在しなかった。

判定基準は ADR-0004 に従う: 形式化は「それを読む機械（または強制力）」を名指しできるときにのみ行う。

実地の一件目（2026-07-06、greenfield SNS の UI 刷新）で screen ビューへの需要が初めて現れ、次の形で決着した: コンポーネント・デザイントークンの詳細は**コードが唯一の機械可読正本**（型定義・CSS 変数・Storybook）であり、設計層に複製するとどちらかが腐る。設計層に残るのは視覚言語の採用**決定**（ADR）とデザインシステムという**モジュールの存在**（static 層）まで。すなわち、需要は既存能力（三段選択の 1〜2 段目 — docs/boundary.md）で満たされ、ビュー型は要らなかった。

## Decision

1. **ビュー型の追補は、ツール能力としても需要駆動とする**。named consumer（そのビューを読む機械または強制力）を名指しできる実プロジェクトが現れた時点で、型ごとに個別に追補する
2. **spec §4 の prefix 列挙は名前空間の予約であり、追補の約束ではない**。列挙された型が実装されないまま残ることを明示的に許容する。C6 の fail-closed はこの方針の歯である
3. 追補の機構（宣言構文・リンク義務・scaffold・C6 結線）は、named consumer が最初に立つ型で検証する。**permission が有力**（consumer 候補 = 権限マトリクスとコード定義の突合テスト）。以後の型は同じトリガで個別に追補する（spec §12 と同一）
4. **プロジェクトへの適用も消費者駆動とする**。consumer 不在のビュー書き起こし・移行はセレモニーであり行わない（ADR-0004 の適用。手順は docs/adoption.md Step 4）
5. ビュー型の追補は加算的変更であり、format-version は上げない（ADR-0016）

## Alternatives Considered

### 列挙済みビュー型を計画的に順次実装する

- **Pros**: spec の列挙と実装が一致し、誤読の余地が消える
- **Cons**: consumer 不在の型はスキーマの設計材料（リンク義務を何にするか）が存在せず、推測で固めたスキーマは最初の実プロジェクトで壊れる
- **Why not**: 読む機械のない形式はセレモニーになる（ADR-0004）。screen の実地一件目が「コード正本で足りる」と決着した事実は、列挙が需要を予言できないことの証跡である

### 列挙から未実装型を削除する

- **Pros**: spec が現状と完全一致する
- **Cons**: prefix の名前空間予約（将来の追補時に ID 文法・既存文書と衝突しない保証）を失う
- **Why not**: 予約は追補時の互換性のために安価で有用。必要なのは削除ではなく「予約であって約束ではない」の明文化

## Consequences

- screen ビューは consumer 未特定のまま残る。視覚詳細レベルで立つ見込みは低い（コードが正本）。立つとすれば構造の骨格（画面 ↔ ルート ↔ ユースケース ↔ アクターの対応）に突合の機械（例: ルート同期テスト）が要求されたときに限る
- ADR-0002 のビュー列挙は「有効化されうる名前空間」と読み替える（同 ADR に修正注記を付す）
- 需要の観測点は導入プロジェクトの findings（docs/findings/）と論点起票に置く。「要望が来ないこと」は「需要がないこと」を意味しないが（ADR-0021）、consumer を名指しできない要望は本 ADR の 1 を満たさない
