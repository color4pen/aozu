# ADR-0024: 依存引用 — request の依存行で被覆と依存の辺を分離する

- Status: accepted
- Date: 2026-07-10

## Context

request 文書中の `[[id]]` は被覆の宣言と定義されており（ADR-0012・integration.md §1）、入口ゲートは implemented 要素の引用を要素単位で不合格にする（R2）。この単義性は「設計 delta を経ずに実装済み要素へ触る」ことを防ぐ歯として正しいが、**「この request が変更しない依存要素」を機械可読に宣言する場所が無い**。実装済みの要素を文脈として参照する実需は実地で確認済みであり（docs/findings/aosora-2026-07-04.md #1: 実装済み ent を依存として引用した request が R2 で弾かれた）、現運用の回避はコード表記による参照抽出からの除外だが、非自明であり、依存という辺が構造から消える——「列挙されない依存は禁止」の fail-closed と逆行する。

根本原因は一つの構文への意味の過積載である: 引用の辺には**被覆**（この request が変更する要素）と**依存**（この request が前提とする要素）の二種類の実需があるのに、文法は一種類しか持たない。

## Decision

1. **依存行**: request 文書中の行頭 `依存: [[id]](, [[id]])*` の行を依存宣言と定める。依存行上の引用は**依存引用**、それ以外の本文引用は従来どおり**被覆引用**である。依存行は 1 文書に複数書いてよく、文書中の位置を問わない
2. **入口ゲートの二種類化**: `check --request` は依存引用に対して実在解決のみを検証し、要素の状態を問わない（implemented 要素の依存引用が正当になる）。被覆引用の検証（designed または requested のみ合格）は変えない。`--require-citation` が数えるのは被覆引用のみ
3. **被覆からの除外**: coverage は依存引用を被覆集合に数えない
4. **回避運用の廃止**: コード表記で参照抽出から逃がす依存表現は用いない。依存はすべて依存行に置き、機械可読にする

## 却下した代替案

- **参照文法の拡張（`[[~id]]` 等の文脈引用記法）**: 参照文法（spec §6）への変更であり format-version に触れる。辺の型付けは「参照がどの構造に現れるか」で与える既存パターン（mod の `実装:` 行・perm の操作行・seq の登場要素リスト）があり、行文法で足りる
- **現運用（コード表記による除外）の明文化**: 最小コストだが依存の再不可視化であり、fail-closed の原則と逆行する
- **request 文書への節（見出し）構造の要求**: request テンプレートは消費者が注入する（ADR-0012）。見出し階層への要求はテンプレート構造への介入になる。行文法は位置を問わず、テンプレート非依存を保つ

## Consequences

- integration.md §1（依存行の文法と検証の二種類化）・§4（消費者前提への追記）を改訂する
- 消費者前提は「request 文書が本文中の `[[id]]` 引用を受け入れること」に「依存を宣言する場合は行頭 `依存:` の行を書けること」が加わる。行はどの位置でも有効であり、テンプレートへの構造要求は増えない。依存行を使わない従来の request はすべてそのまま有効（追補的変更・format-version 増分なし）
- 依存引用は「どの request がどの要素を前提としたか」の機械可読な辺になり、trace 動詞（未実装）の材料になる
- 実装の触点は `check --request`（依存行の抽出と検証の分岐）と coverage（被覆集合からの除外）。request 導出側（derive テンプレート・実装パイプラインのガイダンス）には依存行の案内を追加できるが、知らない消費者の既存運用は壊れない
