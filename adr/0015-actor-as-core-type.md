# ADR-0015: アクターの一級化 — act 型をコアの domain 層に追加する

- Status: accepted
- Date: 2026-07-02

## Context

業務系 SaaS でのドッグフーディング（docs/findings/clearflow-2026-07-02.md）で、ビューを一つも有効化していない素のコア 3 層の時点で、動的構造が破綻した。閉包規則 C5 が seq の登場要素を mod（コードのモジュール）に限定するため、シナリオの主語（ロール・承認者・委任先）を書けず、seq が「レイヤ間のデータ移送図」に退化した。「引合の案件化」の設計上の本質は「manager 以上ができる」だが、その主語が形式から抜け落ちる。

選択肢は三つあった:

1. act 型をコアに新設する
2. permission / external 等のビュー有効化を seq のアクター表現の前提にする
3. 現状維持（アクターは散文で書く）

実地の証拠は 1 に傾いた。ロールは画面や権限マトリクスより**先に**、シナリオの主語として要求される。またビューの中で最需要の permission は本質的に「act × 操作」のマトリクスであり、act がコアに無ければ定義できない。案 3 は「設計上最も重要な情報が機械可読の平面から抜ける」ことを恒久化する。

## Decision

- **act 型（アクター: ロール・主体）をコアの domain 層に追加**する。`design/domain/actors.md`、見出し要素。本文は「誰であるか・何に責任を持つか」の散文まで
- **C5 を改訂**: seq の登場要素は「mod または act」に解決される
- C11 の domain 層 prefix 集合に act を含める（act は domain の概念として domain 内から参照でき、static / dynamic からも参照できる）
- 操作権限の詳細（act × 操作のマトリクス）は permission ビューの領分とし、act はその土台の宣言に留める
- 加算的変更であるため format-version は 0 のまま

## Consequences

- 業務系の seq に主語が戻り、「誰の・何の業務か」が参照グラフに乗る
- domain 層を有効化しないプロジェクト（段階① + dynamic）では act は使えないが、段階縮退（C3 / C5 の無効型 skip）により無害
- permission ビューを定義する前提が揃う
- CLI ツール等のアクターが自明なプロジェクトでは actors.md を書かなくてよい（任意ファイル）
